## 1. qa_diff — 「지적 밖 변경」 찾기 ✅

```bash
cd "<국가데이터처>"
python3 _dev/qa/qa_diff.py <앞판.mp4> <새판.mp4> \
  --allow 10:10-10:30 --allow 13:50-14:05 \   # 민석이 지적한 구간(새 판 시각). 여러 번 가능
  --out ~/Movies/video_qa/5강_v11_v12
# 옵션: --pad 1.0 (허용 구간 앞뒤 여유, 기본 1초) · --no-sheets (비교 jpg 생략)
```

결과
- `diff_report.md`: **「⚠ 지적 밖에서 바뀐 곳」 표**(새 판 시각 · 갈래 · 앞 판 시각 · 비교 jpg) + 지적 구간 안 변경 목록
- `diff.json`: 같은 내용(기계용)
- `sheets/NN_갈래_초.jpg`: 지적 밖 변경마다 **왼쪽 = 앞 판 · 오른쪽 = 새 판** 같은 순간 프레임(최대 60장)
- 16분 영상 2개 기준 처음 약 20초, 캐시 뒤 2초.

동작
- 두 판의 길이가 달라도 된다. 0.1초 단위로 같은 장면을 찾아 맞춘 뒤 비교한다(쉼 삽입·삭제 판 대응). 자막바는 빼고 맞추므로 자막만 바뀐 판도 장면이 어긋나지 않는다.
- 세 갈래로 나눈다: **화면**(자막바 위) · **자막바**(아래 22%) · **소리**(24밴드 스펙트럼, 둘 다 −50dBFS 아래인 룸톤 구간은 뺌).
- 화면 판정 = 192×108 회색조를 12px 칸으로 나눈 뒤, 칸 안 가로줄·세로줄 평균 차의 최댓값(`linemax`). **2px 테두리 하나 바뀐 것, 자막 마침표 하나 붙은 것까지** 잡힌다. 0.3초 미만 차이는 버린다.

### 검증: 5강 R25 v7 → v8 (지적 = 10:17 씬23 · 13:56 씬28 테두리 · 15:41 클로징 + 자막 전수 수정)
`python3 _dev/qa/qa_diff.py …v7.mp4 …v8.mp4 --allow 10:10-10:30 --allow 13:50-14:05 --allow 15:35-16:08 --out ~/Movies/video_qa/5강_v7_v8`
결과 `~/Movies/video_qa/5강_v7_v8/diff_report.md` (변경 51곳, 지적 밖 43곳)

| 알려진 사실 | 도구 결과 | 프레임 확인 |
|---|---|---|
| 씬23 10:17 탭 교체 (지적) | 화면 10:14.9~10:19.5 「허용」 | ✅ |
| 씬28 13:56 테두리 지속 (지적) | 화면 13:55.8~13:58.9 「허용」 | ✅ (처음 지표로는 놓쳤다 → 선 감지 지표로 바꿔 잡음) |
| 자막 띄어쓰기·표기 12줄 수정 (`_orders/검수_R25_v8_자막전수.md`) | 자막바 13구간(0:08.6·0:28.0·1:01·1:14·2:27·2:50·3:04·3:49·8:34·8:45·10:40·11:28·15:53) | ✅ `sheets/01_자막바_28.0.jpg` = 「출발점입니다」→「출발점입니다.」 마침표 |
| **BGM 이음매 18곳 수정이 전 구간 음악을 바꿈**(민석 「수정한 것만 반영하면 되는데 왜 다른 것까지 망쳤냐」) | 소리: 0:31~15:43 거의 전 구간 「밖」 변경, 스펙트럼 차 7~16dB | ✅ 민석 반려 원인과 일치 |
| (몰랐던 것) 테두리 지속 규칙 R25_V8 을 전 씬에 적용한 여파 | 화면 「밖」 3:01·3:24·5:18·6:10·6:50·9:27·12:03~12:07 | ✅ 3:02·3:24·5:18·6:50·9:27·12:03 프레임 대조로 실제 테두리 유무·줌 카드 위치 차이 확인(오탐 아님) |

→ **v8 을 민석에게 올리기 전에 이 도구를 돌렸다면, 「지적 밖 변경 43곳(소리 전 구간 포함)」이 게시 전에 보였다.**

### 한계(꼭 읽기)
- **오탐 가능**: 같은 소스를 재렌더하면 인코딩 잡음이 생긴다. 실측 잡음은 90%=1, 99%=2.5(문턱 6)로 v7→v8 에서 화면 오탐은 0건이었다. 하지만 **AE 재렌더 전체본**처럼 소스가 통째로 바뀐 판이면 미세 잡음이 늘 수 있다. 판정은 반드시 `sheets/` jpg 로 눈 확인한 뒤에 한다.
- **누락 가능**: 0.3초 미만 화면 변화(1~2프레임 깜박임·검은 프레임)는 버린다 → 검은 프레임은 별도 전 프레임 `blackdetect`로 본다. 192×108 에서도 안 보이는 아주 작은 변화(1px 이동)는 못 잡는다.
- **소리 갈래는 「바뀌었다」만 말한다.** 좋아졌는지 나빠졌는지, 대사인지 BGM 인지는 모른다 → 원인은 **대사·BGM 스템을 갈라** 다시 잰다(메모리 `measure-audio-by-stems-not-mix`).
- 새로 생긴 장면(앞 판에 없던 프레임)은 「앞 판에 없음」으로 표시된다. 쉼을 길게 넣은 판에서 이게 많이 나오는 건 정상.
- `--allow` 는 **새 판 시각**이다. 앞 판 시각으로 넣으면 길이가 바뀐 판에서 엇나간다.

### 쓰는 법(제작 절차에 넣을 자리)
1. **마스터를 POC 에 올리기 전**, 방장이 `직전 게시판 → 새 판`으로 돌린다. `--allow` = 이번 라운드에서 민석이 지적한 구간 전부.
2. 「지적 밖」 표의 줄마다 `sheets/` jpg 를 보고 **의도한 것 / 의도 안 한 것**으로 나눈다. 의도 안 한 변경이 하나라도 있으면 게시하지 않고 되돌린다.
3. 의도한 「지적 밖」 변경(예: 전수 자막 수정)은 POC 보고에 **「지적 밖 변경 N곳 = 이유」**를 한 줄씩 적는다. 민석이 그 구간만 보면 되게.
4. 민석은 「지적 구간 + 지적 밖 변경 목록」만 확인하면 된다. 전체 20분 재시청이 필요 없어지는 게 목표다.

## 2. qa_scan — 한 판 전수 훑기 🚧 개발 중 (PASS 근거로 쓰지 말 것)

```bash
python3 _dev/qa/qa_scan.py <마스터.mp4> --out ~/Movies/video_qa/scan_v12 [--skip-black]
```
- 무음(디지털 <−65 0.1초↑ · 아주 조용함 <−52 0.3초↑) · 급락(0.1초에 20dB↑, 앞이 −35 이상) · 전 프레임 검은 화면 · 통합 LUFS·True Peak.
- 확인된 것: 5강 v6 의 **15:41.9 「클로징 음악 뚝」을 급락으로 잡음**(민석이 v8 에서 지적한 그 자리, v6 에도 있었음).
- ❌ 미검증·문제:
  - **지직(조각 루프)**: v6 씬4 2:39(−53dBFS, BGM 아래)를 **못 잡는다.** 기존 `5강…/_planning/R25/clw/v7/loopscan.py` 도 합본에선 OK 로 지나간다(BGM 이 덮음). → 지직은 지금처럼 **씬 파일(BGM 섞기 전)에 loopscan** 으로 본다. qa_scan 의 지직 줄은 무시.
  - 급락·조용함은 정상 문장 끝 쉼도 섞여 나온다(v6 에서 급락 15·조용함 13). 「어디를 들어볼지」 후보 목록이지 판정이 아니다.

## 3. pstack 에서 가져온 제작 절차 (cursor/plugins `pstack` · poteto)

코드용 플러그인이라 통째로 깔지 않는다. 아래 4가지만 국가데이터처 방식으로 옮긴다.

### ① 오더 = 브리프 양식 (출처: `poteto-mode/playbooks/orchestrate.md` 「The brief」)
담당 창에 보내는 모든 오더(재오더 포함)는 아래 칸을 다 채운다. **빈칸이 있으면 오더를 내지 않는다.**
```
목표      한 문장. 대화 맥락 없는 사람이 읽어도 할 수 있게
범위      손대는 파일·씬 / 손대지 않는 파일(남의 씬·공용 렌더러·조립기)
근거      민석 원문(그대로) · 캡처 경로 · 앞 판 파일명·시각
합격      확인 가능한 기준 한 줄씩(예: 「선행 0」「v11 대비 지적 밖 변경 0」)
검증      실행할 명령 그대로(qa_diff 명령 포함) + 알려진 함정
보고      판 파일명·md5·실제로 돌린 명령·벗어난 것·남은 것
상시규칙  standing.md 전문 붙여넣기   ← 재오더 때 빠뜨리는 게 반복 반려의 원인
```
- 「상시 규칙」 = 한 줄에 하나씩 번호 매긴 목록 파일(예: `5강…/_orders/standing.md`). **같은 지시를 두 번 하게 되면 쓰기 전에 그 파일에 한 줄 추가**한다(pstack `principle-encode-lessons-in-structure`).

### ② 「안전한 이유 한 가지」를 돌려서 증명 (출처: `skills/blast-radius`)
고치기 전, 이 수정이 다른 데를 안 망가뜨리는 근거를 **한 문장**으로 적고 **실행으로 증명**한다.
예: 「BGM 은 15:35 이후만 바뀐다」 → 고친 뒤 `qa_diff --allow 15:35-16:08` 의 소리 「밖」 = 0 이 증명. 증명 못 하면 보고에 「미증명」이라 쓴다.
v8 사고(한 곳 지적 → 18곳 수정)는 이 한 줄을 안 적어서 났다.

### ③ 자기 보고는 증거가 아니다 (출처: `principle-prove-it-works`)
담당 창 「완료·통과」 보고 ≠ 합격. 방장은 **실제 마스터 파일**에 qa_diff 를 직접 돌린 결과로만 게시한다. 검증 못 했으면 「미확인」이라고 쓴다.

### ④ 검수 결과는 4칸으로 (출처: `skills/interrogate` lead judgment)
검수 창(코덱스·클로드) 보고는 이 네 칸으로 정리한다. 두 창이 따로 같은 것을 잡으면 신뢰도가 가장 높다.
| 칸 | 뜻 |
|---|---|
| 바로 고칠 것 | 민석 지적 위반·의도 안 한 변경·소리 깨짐 |
| 민석 판단 필요 | 취향·대본 문제·선택지(→ 방장이 한 장으로 묶어 올림) |
| 참고 | 맞지만 지금 고칠 가치 낮음 |
| 기각 | 오탐(이유 한 줄) |
